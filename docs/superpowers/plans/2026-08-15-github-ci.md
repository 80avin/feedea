# GitHub CI — Cross-Platform Builds Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add GitHub Actions workflows that test the app on every push/PR and build release binaries for Linux x64/arm64, Windows x64, and macOS arm64/x64 on version tags.

**Architecture:** A committed `rust-toolchain.toml` pins stable. `.github/workflows/ci.yml` runs the full test suite on `ubuntu-latest`. `.github/workflows/release.yml` uses a native-runner matrix to build a release binary per target (bun then cargo), runs the end-to-end smoke test on the linux-x64 job, and attaches all binaries to a draft GitHub Release.

**Tech Stack:** GitHub Actions, oven-sh/setup-bun, dtolnay/rust-toolchain, Swatinem/rust-cache, softprops/action-gh-release, bash/PowerShell.

## Global Constraints

- Binary name is `feedea` (cargo package `feedea`). Artifacts: `feedea-<os>-<arch>[.exe]`.
- Every build job must run `bun install` + `bun run build` (in `frontend/`) BEFORE `cargo build --release` — `build.rs` panics if `frontend/dist/index.html` is missing.
- Toolchain is stable via `rust-toolchain.toml` (channel stable, components rustfmt + clippy). Verified: compiles clean on stable 1.97.1.
- Release workflow triggers on tags `v*`; the Release is created as a draft.
- Smoke test runs on the linux-x64 job only, using the just-built binary at `target/release/feedea`.
- Windows job uses PowerShell for the rename step; all other jobs use bash (default on ubuntu/macOS).
- No comments in workflow files beyond what GitHub Actions itself expects; keep YAML clean and minimal.
- Commit after each task with the exact message given.

### Task 2: CI workflow on push/PR

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `rust-toolchain.toml`, `frontend/package.json` (bun scripts), the Makefile's `test` recipe as reference.
- Produces: a `test` job on `ubuntu-latest` that runs fmt/clippy/tests + frontend typecheck/lint. This is the per-push/PR quality gate.

- [ ] **Step 1: Create `.github/workflows/ci.yml`**

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: oven-sh/setup-bun@v2

      - uses: dtolnay/rust-toolchain@stable

      - uses: Swatinem/rust-cache@v2

      - name: Install frontend deps
        working-directory: frontend
        run: bun install

      - name: Build frontend
        working-directory: frontend
        run: bun run build

      - name: Format check
        run: cargo fmt --check

      - name: Clippy
        run: cargo clippy --all-targets -- -D warnings

      - name: Cargo tests
        run: cargo test --all-targets

      - name: Frontend typecheck
        working-directory: frontend
        run: bun run typecheck

      - name: Frontend lint
        working-directory: frontend
        run: bun run lint
```

Run a YAML parse check (e.g. `python3 -c "import yaml,sys; yaml.safe_load(open('.github/workflows/ci.yml'))"`; if PyYAML is unavailable, use `ruby -ryaml -e 'YAML.load_file(".github/workflows/ci.yml")'` or `bunx yaml-lint`). Expected: no parse errors.

### Task 3: Release workflow — matrix build + smoke + upload

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: `rust-toolchain.toml`, `frontend/package.json`, `scripts/smoke.sh` (linux-x64 smoke gate), the artifact naming `feedea-<os>-<arch>[.exe]`.
- Produces: a `build` matrix job (5 targets) + a `release` job that attaches all binaries to a draft GitHub Release on `v*` tags.

- [ ] **Step 1: Create `.github/workflows/release.yml`**

```yaml
name: Release

on:
  push:
    tags: ["v*"]

permissions:
  contents: write

jobs:
  build:
    name: ${{ matrix.target }}
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        include:
          - os: ubuntu-latest
            target: linux-x64
            artifact: feedea-linux-x64
          - os: ubuntu-24.04-arm
            target: linux-arm64
            artifact: feedea-linux-arm64
          - os: windows-latest
            target: windows-x64
            artifact: feedea-windows-x64.exe
          - os: macos-15-arm64
            target: macos-arm64
            artifact: feedea-macos-arm64
          - os: macos-15
            target: macos-x64
            artifact: feedea-macos-x64
    steps:
      - uses: actions/checkout@v4

      - uses: oven-sh/setup-bun@v2

      - uses: dtolnay/rust-toolchain@stable

      - uses: Swatinem/rust-cache@v2

      - name: Install frontend deps
        working-directory: frontend
        run: bun install

      - name: Build frontend
        working-directory: frontend
        run: bun run build

      - name: Build release binary
        run: cargo build --release

      - name: Smoke test (linux-x64 only)
        if: matrix.target == 'linux-x64'
        run: bash scripts/smoke.sh

      - name: Rename binary (unix)
        if: runner.os != 'Windows'
        run: cp target/release/feedea "${{ matrix.artifact }}"

      - name: Rename binary (Windows)
        if: runner.os == 'Windows'
        shell: pwsh
        run: Copy-Item target/release/feedea.exe "${{ matrix.artifact }}"

      - name: Upload artifact
        uses: actions/upload-artifact@v4
        with:
          name: ${{ matrix.artifact }}
          path: ${{ matrix.artifact }}

  release:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v4
        with:
          path: artifacts

      - name: List artifacts
        run: ls -R artifacts

      - uses: softprops/action-gh-release@v2
        with:
          files: artifacts/**/*
          draft: true
```

Note: on linux-x64 the smoke test runs `bash scripts/smoke.sh`, which expects the release binary at `target/release/feedea` (already built by the previous step). The script's auto-build branch is a no-op there.

Important runner facts (verified against actions/runner-images, 2026-08):
- `macos-13` is RETIRED and `macos-14` images are deprecated; the current macOS runners are `macos-15` (Intel x64) and `macos-15-arm64` (Arm64). The matrix uses those.
- The rename step MUST NOT use a bash-conditional under a pwsh shell. It is split into two steps keyed on `runner.os` with an explicit `shell: pwsh` on the Windows one. Do not reintroduce a single mixed-shell rename step.

- [ ] **Step 2: Validate the YAML** (same approach as Task 2 Step 2). Expected: no parse errors; actionlint should NOT warn about the runner labels (if actionlint warns about `macos-15`/`macos-15-arm64`, confirm those are the correct current labels per actions/runner-images and note it).

- [ ] **Step 3: Cross-check the rename on Windows**

Verify `target/release/feedea.exe` is the correct path on `windows-latest` (cargo outputs `feedea.exe`; the `Copy-Item` step targets it and runs under `shell: pwsh`). Also confirm the smoke test's fixture server (`python3 -m http.server`) exists on `ubuntu-latest` (it does).

- [ ] **Step 4: Commit**

```bash
git add .github/workflows/release.yml && git commit -m "ci: add tagged release build matrix with smoke gate"
```
